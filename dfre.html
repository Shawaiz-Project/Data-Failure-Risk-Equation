04 / Quick start

The one-liner accepts four precomputed signals. Each signal is a value from zero to one; zero means no observed issue and one means maximal issue for that signal.

Python · core only
import dfre

result = dfre.score(
    missing=0.08,
    invalid=0.04,
    drift=0.12,
    uncertainty=0.20,
    n=1000,
)

print(result.risk, result.band, result.action)

Use the library score in production. This page’s workbench is a browser-side learning aid; it does not inspect a dataset or call the Python package.

05 / Signals

Core signals can be supplied directly or computed from batches with signal classes. In v0.2.0, four optional signals extend scoring to freshness, batch volume, schema, and outliers.

SignalWhat it measuresUseful details
M · MissingnessFraction of missing values, with configurable sentinel handling.MissingnessSignal(sentinels=None)
V · InvalidityFraction of rows failing per-column boolean validation rules.InvaliditySignal(rules); inspect failing columns.
D · DriftDistribution change from a reference batch across numeric or categorical fields.PSI by default; KS and Wasserstein require SciPy.
U · UncertaintyPredictive uncertainty from probability outputs or MC-dropout samples.Entropy, margin, or MC-dropout methods.
FreshnessAge of the latest data relative to an SLA; capped at 1.FreshnessSignal(sla_seconds)
VolumeLog-ratio anomaly between observed and expected row counts.VolumeSignal(expected_rows)
SchemaMissing/extra columns and optional dtype contract failures.SchemaSignal(expected_columns)
OutliersFraction of rows extreme in any watched numeric column.IQR or z-score method.

Normalize deliberately. DFRE combines signal values as comparable [0, 1] indicators. The value’s meaning depends on each signal’s definition and chosen scale.

06 / Builder pipeline

Use the builder when you want DFRE to compute signals from each incoming batch, compare against reference data, and attach context to extra signals.

Python · pandas extra
import numpy as np
from dfre import DFREBuilder, DriftSignal, InvaliditySignal
from dfre import FreshnessSignal, MissingnessSignal, OutlierSignal
from dfre import SchemaSignal, UncertaintySignal, VolumeSignal

rules = {"age": lambda s: s.between(0, 120)}
pipeline = (
    DFREBuilder()
    .with_missingness(MissingnessSignal())
    .with_invalidity(InvaliditySignal(rules))
    .with_drift(DriftSignal(["age", "income"], statistic="psi"))
    .with_uncertainty(UncertaintySignal(method="entropy"))
    .with_extra_signal("freshness", FreshnessSignal(sla_seconds=3600), weight=0.8)
    .with_extra_signal("volume", VolumeSignal(expected_rows=10_000), weight=0.5)
    .with_extra_signal("schema", SchemaSignal(["age", "income"]), weight=1.0)
    .with_extra_signal("outliers", OutlierSignal(["age", "income"]), weight=0.5)
    .build()
)

result = pipeline.evaluate(
    incoming, reference, probabilities,
    context={
        "freshness": (last_updated,),
        "volume": (len(incoming),),
    },
    metadata={"source": "customer_feed"},
)
print(result.risk, result.band, result.extra_signals)

Context values: extra signal inputs use the key passed to with_extra_signal. For volume, pass the current row count; the signal itself has the expected row count.

07 / Calibration

Learn interaction parameters and decision thresholds from historical batches with known outcomes. Calibration needs both successful and failed examples; tune against your real false-positive and false-negative costs.

Python · pandas history
from dfre import calibrate, calibrate_thresholds
from dfre.calibration.thresholds import to_policy
from dfre.core.equation import dfre_array

# history columns: M, V, D, U, failed
fit = calibrate(history, label_col="failed", cv_folds=5, bootstrap=200)
scores = dfre_array(
    history.M.to_numpy(), history.V.to_numpy(),
    history.D.to_numpy(), history.U.to_numpy(),
    lam=fit.lam, gamma=fit.gamma,
)
thresholds = calibrate_thresholds(
    history.failed.to_numpy(), scores, cost_fp=1, cost_fn=10,
)
policy = to_policy(thresholds)

print(fit.lam, fit.gamma, fit.auc, fit.auc_ci)
print(policy.to_dict())
Do not calibrate on labels invented from the same DFRE score. That leaks the answer into the target and produces misleading performance. Use downstream incident outcomes and validate on held-out history.

Equation parameters

λ controls pairwise interaction strength; γ controls the higher-order product term. Cross-validation helps choose settings that rank historical failures, but it does not guarantee future performance.

Decision thresholds

Threshold calibration minimizes the specified weighted error cost. Choose cost_fn and cost_fp to reflect your operational consequences.

08 / Explain & sensitivity

Use the generalized scorer for named signals. The explanation ranks signal contributions; derivatives and perturbation analyses answer different “what should I fix?” questions.

Python
import dfre

signals = {"M": 0.08, "V": 0.04, "D": 0.12, "U": 0.20, "freshness": 0.3}
weights = {"freshness": 0.8}

result = dfre.score_generalized(signals, weights=weights, n=1000)
explanation = dfre.explain(signals, weights=weights, n=1000)
print(result.risk, result.band)
print(explanation.text)
print("Gradient:", dfre.partial_derivatives(signals, weights=weights, n=1000))
print("Tornado:", dfre.tornado(signals, weights=weights, n=1000, delta=0.1))
print("Elasticity:", dfre.elasticity(signals, weights=weights, n=1000))
Generalized: 1 − exp(−[Σᵢ wᵢsᵢ + λΣᵢ<ⱼ wᵢwⱼsᵢsⱼ + γΠᵢsᵢ] / (1 + √N))The generalized equation includes all signal pairs. The four-signal classic equation uses its documented cyclic pairs (MV, VD, DU, UM).

09 / Policies & escalation

A Policy maps score ranges to operational bands. Defaults are starting points, not universal safety thresholds.

BandDefault risk rangeDefault action
LOWrisk < 0.20Continue normal monitoring
MODERATE0.20 ≤ risk < 0.45Open an investigation alert
HIGH0.45 ≤ risk < 0.70Human review and quarantine
CRITICALrisk ≥ 0.70Block batch and page on-call
Python · stateful escalation
from dfre import EscalationPolicy, Policy

policy = Policy(low_max=0.18, moderate_max=0.40, high_max=0.68)
escalator = EscalationPolicy(
    policy,
    consecutive=3,
    escalate_at="HIGH",
    cooldown=2,
)

for result in batch_results:
    effective_band = escalator.classify(result.risk)
    action = escalator.action_for(effective_band)

Escalation adds consecutive-breach escalation and hysteresis to reduce alert flapping. It does not execute pipeline actions for you; connect the resulting action to your own controls.

10 / Monitoring & reports

Persist scored batches as JSONL, inspect rolling statistics, detect trends, route alert payloads to sinks, and render a self-contained HTML report.

Python
import dfre

history = dfre.HistoryStore("dfre_history.jsonl")
router = dfre.AlertRouter().add_sink(dfre.file_sink("alerts.jsonl"))

result = dfre.score(0.08, 0.04, 0.12, 0.20, n=1000)
snapshot = dfre.make_snapshot(
    0.08, 0.04, 0.12, 0.20, 1000,
    batch_id="daily-2026-09-26",
    source="customer_feed",
)
history.append(result, batch_id=snapshot.batch_id)
router.dispatch(snapshot, result)

trend = dfre.TrendDetector().analyze(history.risks())
print(history.stats(), trend.direction, trend.alarm)

html = dfre.generate_html_report(history.load(), title="Daily pipeline risk")
with open("dfre_report.html", "w", encoding="utf-8") as report:
    report.write(html)

13 / Interpretation & limits

Risk score is not a failure probability. DFRE produces a bounded composite score. Only empirical calibration against relevant, representative outcomes can establish how scores relate to risk in a specific workflow.
  • A score summarizes the signals you provide; it cannot detect a failure mode that has no input signal.
  • Signal definitions, reference windows, weights, batch size, λ, γ, and policy thresholds all affect results.
  • The 1 + √N normalization lowers a score as sample size grows; interpret this behavior in the context of your own batch semantics.
  • Use incident history for calibration, reserve holdout data for evaluation, and monitor performance as the data changes.
  • DFRE is a monitoring and decision-support layer, not a replacement for validation, domain review, or incident-response controls.
